# Фундамент миграции: отчёт

Статус: подготовка модели и ограниченная TEST-проверка. Производственный SOURCE
пока пуст, массовая миграция не выполнялась. Исторический authority не переключён.
Этот отчёт описывает результат работы; нормативные правила находятся в AGENTS.md.

## Прочитанные инструкции и файлы

Обязательные: `dimnadvod/AGENTS.md`,
`dimnadvod/contracts/content-delivery/AGENTS.md`, `test-app/AGENTS.md`.
Их точные blob SHA, ревизии репозиториев и полный перечень прочитанных старых
источников записаны в [baseline.yaml](baseline.yaml).

Старый репозиторий исследован через дерево путей, индекс маршрутизации и
применимые инструкции. Прочитаны необходимые стандарты, статьи Конституции,
правила и хронология Канона, структура глав, открытые вопросы, три персонажа,
А316СК, признание и выбранная фотография. Дополнительно сопоставлены карточки
кадра камеры и фотографии Артура при выборе минимального примера. Индекс
использован для поиска, не как источник истины. Для изображения камеры проверены
только blob SHA и размер. Бинарные файлы не загружались.

`novogram-app` закреплён только по HEAD; его JS, JSON, SQLite и runtime не
читались и не переносились: для фундамента первичных источников достаточно.
Локальная старая копия с незакоммиченными изменениями не использовалась вместо
закреплённой GitHub-ревизии. Русские зеркала новых инструкций не читались.

## Предлагаемые решения

- Физическая структура и команды: [README](../README.md).
- Универсальный frontmatter: только `id`, `type`, `name`; остальные поля зависят
  от типа. Первый этап: character, vehicle, material, event, group, chapter, slice.
- Stable ID: неизменный зарегистрированный prefix + ASCII kebab-case. Существующие
  `char-*` и `doc-sergey-confession` сохранены; подтверждённые исторические
  префиксы `car-` и `material-` тоже разрешены. Предварительные ID автомобиля,
  фотографии, события и координат существуют только внутри TEST.
- Одна типизированная связь хранится у владельца; обратные ссылки строит индекс.
  Новое владение машиной будет event-effect, а не копиями по главам.
- Событие владеет изменением состояния. Интервалы действия и состояние на дату
  вычисляются. Простые постоянные факты, например дата рождения, не обёрнуты во
  временные структуры.
- Знание адресует утверждение через `owner_ref + key`. Текст признания принадлежит
  материалу; статус «сообщено Сергеем» не превращает его в объективную истину.
- Доступность материала, открытие в конкретной сессии и знание различаются.
  Открытие в тесте передаётся внешним runtime-параметром.
- Slice содержит время, наблюдателя и главу. Глава ссылается на входной slice;
  она не хранит вторую дату или список скопированных состояний.
- Индекс и результаты запроса — DERIVED. YAML-карточки — будущий SOURCE.
  JSON/SQLite не используются как авторская база.
- Baseline фиксирует именно исследованный объём, без фиктивного «весь репозиторий
  обработан». Формат будущего content lock задан в
  [content-lock.schema.yaml](../contracts/content-delivery/content-lock.schema.yaml).

## Проверка на реальных объектах

Изолированный [пример](../tests/fixtures/migration-probe.yaml) содержит 12
сущностей. Это шесть целевых объектов, событие смерти Анны, группа наблюдателей,
две главы и два slice. Knowledge change задан правилом чтения признания,
ссылающимся на его единственное утверждение, а не отдельной копией текста.

| Объект/свойство | Г1: 2026-02-23 10:00 | Г2: 2026-03-21 |
| --- | --- | --- |
| Сергей, Анна, Вероника | Те же stable IDs | Те же stable IDs |
| Volkswagen Passat А316СК | Одна карточка автомобиля | Та же карточка |
| Анна: world life_status | dead, вычислено из одного события 2025-09-03 | dead, вычислено из того же события |
| Признание Сергея | Недоступно, даже если runtime ошибочно передал opened | Доступно в проверяемом сценарии полученного пакета |
| Знание признания без открытия | Нет | Нет |
| Знание после разрешённого открытия | Нет | Утверждение материала со статусом reported |
| Фото Сергея с неизвестной | Правило доступности Г1; бинарник ещё не создан | То же правило, тот же материал |

Состояние мира не меняется от открытия признания. Указание погибшей Анны в
авторском результате не означает, что всё авторское знание автоматически попало
в player output. Идентичность неизвестной женщины не раскрывается через raw
relations. Player output не содержит авторский индекс, пути, provenance и мир.

Выполнено: **18 автоматических тестов проходят**, пример из **12 сущностей**
валиден. Проверены соответствие provenance ключам baseline, синтаксис YAML схем
и сохранение байтов/mtime при повторной генерации. Повторный CLI-запуск сообщил
`Unchanged`. Итоговые диагностические файлы находятся в
`generated/migration-probe.json` и `generated/migration-probe-opened.json`;
они DERIVED/TEST, целиком предназначены автору и не являются player package.

Г2 имеет точность «день». Совпадающее по дню событие нельзя автоматически
поместить до или после входа в главу; результат остаётся неопределённым. Точная
дата смерти Вероники в тест не внесена. Неизвестное состояние в неполном примере
не означает, что этого факта нет в старом каноне.

## Действительно открытые решения

1. Согласовать смерть Вероники: хронология пишет «До 03.09.2025», карточка и
   признание — 03.09, карточка уточняет 17:00–18:00. Текст признания является
   утверждением; он не разрешает конфликт объективной хронологии.
2. Уточнить необходимую для производства последовательность приговора, создания
   и получения признания. Начало суда 09.03 не является датой приговора.
   Рабочие anchors из нового root используются без изменения старых источников.
3. Определить знание по основной и резервной веткам. Пример ограничен входом Г2
   после состоявшегося перехода и получения пакета; общий механизм ветвления
   пока не реализован. Это не безусловное правило для любого исхода игры.

Не требуют немедленного авторского ответа для этой задачи: технический формат
индекса, имя lock-файла, вычисление возраста из даты рождения. Фотография пока
является запланированным материалом; перед доставкой нужен бинарник и проверка
временной допустимости. Точная дата не обязательна, если источник доказывает
существование к нужному моменту: для фотографии известно, что Анна скачала её
до смерти. Неуточнённая точность Г2 сохранена, а не заполнена догадкой.
